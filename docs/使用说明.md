# 使用说明

本项目是一个由统一音乐时钟驱动的歌词时间轴播放器。公开仓库只包含虚构 Demo；商业歌词、谱图、音频和人工核验数据必须保存在本机的忽略目录中。

## 安装与启动

需要 Node.js 20 或更高版本。

```powershell
npm.cmd install
npm.cmd run dev
```

打开终端中显示的本地地址。未指定 fixture 时，播放器加载公开的虚构 Demo Song。

## 加载本地私有 fixture

1. 把符合 `SongDocument` 格式的 JSON 放入仓库根目录的 `local-fixtures/`。
2. 文件名只使用小写字母、数字、下划线或连字符，例如 `my_song.json`。
3. 启动开发服务器。
4. 在本地地址后增加 `fixture` 查询参数：

```text
http://localhost:5173/?fixture=my_song
```

本机验收文件可通过以下地址加载：

```text
http://localhost:5173/?fixture=xiang_zi_you
```

该入口仅在 Vite 开发服务器中存在。`local-fixtures/` 被 `.gitignore` 排除，生产构建不会复制该目录；构建命令还会检查输出中是否残留本地 fixture 加载代码。

如果文件不存在、JSON 格式错误或未通过 SongDocument 校验，页面会显示错误，不会退回到其他数据或静默修改 timing。

如果本机同时保存了对应的忽略验收测试，可以运行：

```powershell
node --test local-fixtures/xiang_zi_you.acceptance.test.js
```

该测试和真实 fixture 都只存在于本机，不属于公开仓库。

## 播放器操作

- “播放/暂停”：从当前 musical position 开始或暂停。
- “重新开始”：回到歌曲开头。
- “BPM”：改变播放速度，不改变任何歌词 onset 或 tick。
- “节拍鼓”：默认开启，每拍在拍头和 `&` 各响一次；第 1 拍是强大鼓，第 3 拍是次重大鼓，第 2/4 拍是短军鼓，所有 `&` 使用很轻的闭镲提示。
- “节拍声音量”：只改变合成节拍声，不改变浏览器或系统音量。
- “跳转小节”：跳到 performance sequence 中指定的小节。
- 进度条：按 tick seek。
- “简洁/精确”：切换显示密度；精确模式显示完整 `1 e & a` 十六分网格。

歌词从自己的 onset 开始保持高亮，直到下一歌词 onset。空 subdivision 不会清除当前歌词。

浏览器要求音频必须由用户操作启动，因此第一次点击“播放”时才会创建 Web Audio。节拍声使用代码实时合成的鼓声和闭镲式提示，不包含外部 soundfont、商业歌曲音频或复制的第三方采样。

这组声音采用常见架子鼓的“大鼓、军鼓、闭镲”分工，但保留练习节拍所需的强弱层级：第一拍的强大鼓建立小节重心，第三拍用次重大鼓提供次级重音，第二、四拍用更轻更短的军鼓，四个反拍只用高频闭镲承担细分提示。大鼓使用较短的鼓身、中高频鼓槌瞬态和轻微软削波，避免低频拖尾，并让普通电脑音箱也能听见清晰的冲击感。默认节拍音量为 75%。

## 数据格式

公开的完整格式说明和虚构示例见根目录 [README](../README.md)。核心结构如下：

```text
SongDocument
  metadata
  sections[]
    measures[]
      lyricEvents[]: text + onsetTicks + optional step16
  performanceSequence[]
```

`onsetTicks` 是小节内的 canonical timing。对于当前 `PPQ = 480` 的 4/4 fixture，每个十六分音符为 120 ticks，`step16` 必须与 `onsetTicks` 一致。

## 检查与构建

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run e2e
```

生产构建输出位于 `dist/`。它只包含公开 Demo，不包含 `private/`、`local-fixtures/` 或开发环境的本地 fixture 加载入口。

## 版权与隐私

不要把商业歌曲完整歌词、谱图、音频、人工 Ground Truth、Token 或密码复制到公开源码、测试、截图或 Issue 中。提交前可以检查：

```powershell
git status --ignored --short
git ls-files private local-fixtures
```

第二条命令正常情况下不应输出任何文件。
